# 每日情报页改版：当日优先 + AI 日报前置自动生成 — 设计文档

**日期**：2026-07-27
**状态**：已确认（用户逐节批准）
**范围**：单阶段交付——日报生成逻辑抽模块 + 流水线自动生成 + 每日情报页重排

---

## 背景与目标

用户在手机真机验证后反馈（原话）：

> "每日情报应该优先展示当日的情报，也是自动生成 AI 分析的日报，然后找更好的方式展现出来，而不是放到情报的底部，翻好久才看到"

**现状问题**（代码核实）：

1. **日报必须手动生成**：前端只在你点"📋 生成日报"按钮时调 `GET /api/daily-report/{date}`（该端点本身有缓存+无缓存时生成能力，但前端从不自动调用）
2. **日报展示在列表最底部**：`#dailyReportContainer` 被 append 到 `.daily-feed` 末尾（dashboard.html:1466-1467），默认 30 天视图下要翻完所有信号卡才能看到
3. **当日情报无优先级**：默认视图是"最近 30 天"，信号按强度（红/黄/绿）分组，今天的和十几天前的混在一起

**已确认的需求决策**（brainstorming 阶段逐项确认）：

1. **页面结构**：方案 A 今日置顶一体——打开页面就是今日视图：日报卡 → 当日信号 → 折叠的"更早情报"区（已否决：B 双标签——多一层点击；C 摘要横幅——不解决当日优先）
2. **生成时机**：流水线跑完自动生成 + 页面打开时无缓存兜底生成（已否决：仅打开页面时生成——首次要等 30-60 秒）

## 总体架构

```
每日情报页（今日视图）
├── ① 📋 今日摘要卡（置顶，自动加载）
│     GET /api/daily-report/{today} ── 有缓存秒出 / 无缓存后端即时生成
├── ② 今日情报（N 条）
│     GET /api/signals/date/{today} ── 现有卡片+强度分组+AI解读+筛选器
└── ③ ▾ 查看更早的情报（默认折叠）
      展开 = 现有页面原样（日期选择器+天数胶囊+统计卡+列表+生成日报按钮）

日报生成链（共用一份逻辑）
├── src/daily_report.py: generate_daily_report(date)  ← 从 web 端点抽出
├── web 端点 /api/daily-report/{date}                    → 薄壳（422 校验 + 调用）
├── 流水线 SSE 流（手动跑）  → complete 事件后 asyncio.create_task 后台生成
└── 调度器 run_daily_intel  → 流水线结束后同步 await 生成（一次性命令安全）
```

**复用原则**：生成逻辑只有一份（prompt、合规检查、缓存读写不变），端点与流水线都是调用方。

## 组件设计

### 1. `src/daily_report.py`（新模块）

从 `api_get_daily_report`（web.py:876-957）原样抽出：

```python
async def generate_daily_report(date: str) -> dict
    # 返回 {"date", "report", "signal_count", "cached", "error"?}
```

行为与现状逐条一致：
- 缓存命中 → 直接返回 `cached: True`，不调 LLM
- 当日无信号 → 返回"该日期暂无情报数据。"，不调 LLM，不写缓存
- 无 LLM 配置 → 返回配置提示 + `error: "no_llm_configured"`，不写缓存
- LLM 成功 → 合规检查（违规仅记日志）→ `save_daily_report` → 返回
- LLM 异常 → 返回 fallback 文本 + `error`，**不写缓存**（下次可重试）

LLM 配置解析用现有的 `resolve_llm_config`（DB 默认模型优先、环境变量兜底，与 AiTriage/网页源/主题源一致）。max_tokens=2048、60s 超时、prompt 原文、跳过 thinking 块——全部保持现状。

web 端点改为薄壳：保留 422 日期格式校验，其余委托给 `generate_daily_report`。

### 2. 流水线接入（`src/main.py`）

- **SSE 流版**（`run_daily_intel_stream`）：`complete` 事件 yield 之后，`asyncio.create_task(generate_daily_report(today))`——后台生成，不拖住进度面板的完成状态；task 内 try/except 吞错记日志
- **调度器版**（`run_daily_intel`，APScheduler / `--run-now` 调用）：流水线结束后 `await generate_daily_report(today)`，try/except 吞错记日志。同步等待保证一次性命令（`python -m src.main --run-now`）进程退出前生成完毕
- 幂等：`generate_daily_report` 开头查缓存，已有当日缓存直接返回——流水线生成与页面兜底撞车最坏多一次 LLM 调用，可接受
- 日报是附加品：任何失败只记日志，不影响流水线结果与 SSE 事件序列

### 3. 前端重排（`templates/dashboard.html`）

**今日视图**（打开"每日情报"即得，替换现有默认 30 天视图）：

1. **📋 今日摘要卡**：置顶。`renderDailyIntel` 改为今日模式后自动 `loadDailyReport(today)`；卡从 `.daily-feed` 底部移除
2. **今日情报列表**：`loadDateSignals(today)` 的数据 + 现有信号卡片/强度分组/🤖 AI 解读；侧栏来源/强度筛选器照常生效；标题显示"今日情报（N 条）"
3. **▾ 查看更早的情报**：默认折叠。展开后呈现现有页面的全部内容——日期选择器、7/14/30/90 天胶囊、统计卡片、按天范围列表、"📋 生成日报"按钮（查历史日期用）

**空态**：
- 今日无信号：列表区显示"今日暂无情报。点左侧「📡 手动运行每日情报」开始抓取"；摘要卡显示"今日暂无情报"（不生成空日报）

**保留不变**：日期选择器查指定某日、天数胶囊、`loadDailyReport` 的渲染逻辑（`.daily-report-card` 深蓝渐变卡 + `##` 标题替换）、单条 AI 解读、筛选器、SSE 进度面板。手机/桌面共用此结构，无需新增媒体查询。

## 错误处理

| 故障 | 系统行为 | 用户可见 |
|---|---|---|
| 今日无情报 | 不调 LLM，不写缓存 | 摘要卡"今日暂无情报" |
| 无 LLM 配置 | 不写缓存 | 摘要卡配置提示（现状文案） |
| LLM 生成失败 | 不写缓存，记日志 | 摘要卡 fallback 文本；页面下次打开重试 |
| 流水线尾日报生成失败 | try/except 记日志 | 无（流水线结果不受影响） |
| 缓存撞车（流水线+页面同时生成） | 缓存检查幂等 | 无 |
