# 手机浏览器适配 — 设计文档

**日期**：2026-07-26
**状态**：已确认（用户逐节批准）
**范围**：单阶段交付——`templates/dashboard.html` 的响应式 CSS 补丁 + 汉堡抽屉导航

---

## 背景与目标

用户会在手机浏览器上使用本系统的**完整功能**（用户已确认：不只阅读，跑流水线、加信息源、改设置都要在手机上可操作）。

**现状实测**（390×844 视口，iPhone 尺寸，Playwright 截图验证）：

1. **侧栏布局已坏（最严重）**：`body { display: flex }`（第 22 行）与现有媒体查询 `.sidebar { width: 100%; position: relative; height: auto; }`（第 212-216 行）冲突——flex 行容器内 `width:100%` 的侧栏被 flex-shrink 压缩成 ~40px 竖条，文字全部竖排，导航不可用
2. 每日情报页：日期选择行挤压换行，"生成日报"按钮挤成竖条
3. 设置页：自定义源卡片的"编辑/删除"按钮竖排挤压；添加表单换行混乱；大模型输入框占位文字被截断
4. 进度面板：JS 内联样式 `min-width:340px`（第 535 行），小屏溢出
5. 宽表格（持仓明细、季度对比）：无任何手机处理，横向溢出

**已确认的需求决策**（brainstorming 阶段逐项确认）：

1. **使用场景**：完整功能——阅读 + 操作（跑流水线、加信息源、改设置）
2. **导航样式**：汉堡菜单——☰ 点开抽屉式侧栏，现有侧栏内容（季度选择、信号筛选、运行按钮）原样保留
3. **实现路线**：方案 A 响应式 CSS 补丁（已否决：B 手机专用模板——双模板维护成本；C 引入 UI 框架重写——工作量过大）

## 总体架构

```
templates/dashboard.html（唯一改动文件）
├── CSS：新增统一 @media (max-width: 768px) 区块
│   ├── 收编现有 2 条散乱规则（174 行统计卡片 2 列、212-216 行坏规则）
│   ├── 抽屉导航（侧栏 transform 滑出/滑入 + 遮罩 + 手机顶栏）
│   └── 各页面适配规则（第 2-5 节）
├── DOM：新增 2 个元素（手机顶栏、遮罩层）
└── JS：新增 ~25 行（抽屉开关 + 导航监听），改动 1 处内联样式（进度面板）

后端零改动 · API 零改动 · 数据流零变化 · 桌面端像素级不变
```

**桌面端保护原则**：所有新样式关在 `@media (max-width: 768px)` 内，桌面浏览器不执行；新 DOM 元素桌面端 `display:none`；JS 只新增不改动（进度面板除外，见第 4 节）。

## 组件设计

### 1. 汉堡抽屉导航（核心组件）

**新增 DOM（2 个元素）**：

- `.mobile-topbar`：手机顶栏，fixed 顶部全宽，高 52px，含 ☰ 按钮 + 当前页名称。桌面端 `display:none`
- `.mobile-mask`：半透明遮罩（`rgba(0,0,0,.45)`），抽屉打开时盖住内容区，点击收起抽屉。桌面端 `display:none`

**侧栏改造（仅媒体查询内）**：

- 平时：`position:fixed` + `transform: translateX(-105%)`，藏在屏幕左外侧；宽度 `min(78vw, 300px)`
- `.open` 时：`transform: none` 滑出，带阴影，`z-index` 高于遮罩
- `transition: transform .25s` 平滑滑动
- **删除坏的旧规则**（212-216 行的 `width:100%; position:relative`），保留 `.main { margin-left: 0 }`
- 侧栏内部内容（季度选择、信号筛选、运行按钮、页脚）零改动

**主内容区**：`.main` 在手机上 `margin-left:0` + `padding-top: 68px`（给顶栏让位）。

**新增 JS（~25 行，全部为新函数，不改现有函数）**：

- `toggleDrawer(force)`：开关抽屉（`.open` 类切换），带元素存在性检查
- 遮罩点击 → 收起
- 导航项点击监听 → 收起抽屉 + 更新顶栏页名（**新增监听器，不改 `switchTab` 等现有逻辑**）

### 2. 每日情报页

- 日期选择行：`flex-wrap: wrap`，标签/日期框/按钮自然换行，按钮恢复正常尺寸
- 时间胶囊（7/14/30/90 天）：现状已适配，保持
- 统计卡片：保持 2 列（收编 174 行规则）
- 信号卡片：内边距收窄；`word-break: break-word` 防长英文标题/URL 撑破卡片

### 3. 设置页

- 自定义源卡片：横排改**上下两区**——上区源信息，下区"已启用/编辑/删除"横排按钮组
- 添加信息源表单：输入框 `min-width` 清零、`width:100%`，每行一个纵向排列；单选按钮组正常间距
- 大模型表单：2 列输入改 1 列纵向
- **输入框字号 16px**（iOS Safari 对 <16px 输入框聚焦时自动放大页面）

### 4. 季度报告页 + 进度面板

- 页内标签（概览/AI 分析/多源信号/持仓明细）：横向可滑动（`overflow-x:auto`，不换行挤压）
- 宽表格（持仓明细、季度对比）：外层横向滚动容器 + 右缘渐隐阴影提示可横滑。实施时按现有 DOM 核对：已有容器则加 class，无容器则直接对表格父级生效
- matplotlib 图表图片：`max-width:100%; height:auto`
- **进度面板（唯一需要改动的现有 JS）**：第 535 行 `panel.style.cssText` 中的 `min-width:340px` 是内联样式，媒体查询管不到。处理：把宽度相关样式从 JS 字符串移入 CSS class（如 `.progress-panel`），媒体查询内改为 `width: calc(100vw - 32px); max-width: 420px`。纯样式搬家，无逻辑变化

### 5. 全局触控细节

- 可点目标（按钮、导航项、复选框行）最小高度 44px
- 页面边距：`.main` padding 从 `28px 32px` 收为 16px
- 卡片 padding 适当收窄

## 错误处理 / 风险

| 风险 | 对策 |
|---|---|
| 改坏桌面端 | 全部新样式关在媒体查询内；新 DOM 桌面端隐藏；改动前后 1280px 截图逐页对比 |
| JS 报错卡死页面 | 新函数带元素存在性检查；不改动任何现有 JS 函数 |
| 收编丢功能 | 逐条核对现有 2 条规则去向：统计卡片 2 列保留；212-216 行坏规则由抽屉方案替代 |
| 抽屉与现有交互冲突 | 抽屉只是 class 切换，不影响 `switchTab`、SSE、表单提交等任何现有逻辑 |
| 更小的屏（320px） | 宽度全部用相对单位（vw、%、calc），不写死像素 |

单条规则出问题不影响其他规则——CSS 天然隔离。

## 不变更 / 非目标

- 桌面端任何像素不变（769px 以上沿用现有布局，平板不做专门优化）
- 后端、API、数据库、流水线零改动
- 不做手机专用模板、不引入 Bootstrap/Tailwind 等 UI 框架（方案 B/C 已否决）
- 不做 PWA / 添加到主屏 / 原生 App
- 不做暗色模式
- 现有 JS 逻辑（switchTab、SSE、表单、CRUD）一行不改（进度面板内联样式搬家除外）
- 合规红线无影响：纯表现层改动，不涉及任何内容生成
